# Carbon Desk

컨설턴트를 위한 Scope 3 자료 검토 도구. React + TypeScript + Vite / Node.js HTTP + OpenAI Responses API.

## 실행

```sh
npm install
cp .env.example .env
# .env의 OPENAI_API_KEY, OPENAI_MODEL 설정
npm run dev
```

http://127.0.0.1:5173 에서 확인합니다. API는 127.0.0.1:3001에서 실행됩니다. `.env`가 이미 있으면 덮어쓰지 마세요.

```sh
npm run build
npm test
npm start
```

빌드 이후 `npm start`는 3001 포트에서 프런트엔드와 API를 함께 제공합니다.

## 구현 범위

예·아니요 스크리닝과 15개 카테고리 목록(Cat 1 활성) → 목적 안내 → 구매 자료 보유 여부 분기 → Excel/CSV 업로드 → 분석할 시트 1개 선택·헤더 확인 및 전체 데이터 조회 → 선택한 시트의 대표 행 기반 AI 컬럼 분석 → 수동 수정·표준 컬럼 적용 미리보기·검토 확정 → 산정 조건 대화 → 추가 확인 목록·결과 JSON 다운로드.

샘플 구매대장을 내장했습니다. 샘플도 AI 분석 시 실제 API를 호출합니다. AI 없이 수동 연결하는 경로도 제공됩니다. 산정 조건 확인 후 거래 자동 묶음·사용자 규칙·그룹별 산정 방법 선택을 지원합니다. 배출계수 연결 및 실제 배출량 계산은 포함하지 않습니다.

## 데이터 및 운영 범위

- 서버는 매 요청마다 프로젝트 루트의 `.env`를 다시 읽고 상위 환경변수보다 우선 적용합니다. 키 변경 후 재시작은 필요하지 않습니다(서버 코드 업데이트 시 재시작 필요). VITE_ 접두사 환경변수에 키를 넣지 마세요.
- 모델은 `OPENAI_MODEL`로 변경합니다. 기본값은 `gpt-6.1-sol`. 계정의 모델 접근 권한이 필요합니다.
- 파일은 브라우저 메모리에서 파싱합니다. 한 번에 파일 1개, 최대 10MB를 지원합니다. 현재 선택한 시트 1개만 분석하며 최대 200개 컬럼·100,000행을 지원합니다. 다른 시트는 API에 보내거나 분석하지 않습니다. 크기 제한 초과 시 데이터를 잘라 보내지 않고 오류를 표시합니다.
- 브라우저는 선택한 시트의 표 데이터만 로컬 서버에 전달하지만, LLM에는 해당 시트의 헤더와 앞·중간·끝에 고르게 분포한 최대 24개 대표 행만 전송합니다. 컬럼이 많으면 예시 행 수를 줄이고 긴 예시 셀은 160자까지 전달합니다. 원본과 미리보기 값은 변경하지 않습니다. OpenAI 요청은 `store: false`로 설정합니다.
- 서버에 원본 파일·분석 내역을 저장하지 않으며 앱에서 새로고침 시 작업 상태가 초기화됩니다. 분석 완료 후 선택한 시트의 컬럼을 확인하면 검토를 확정할 수 있습니다. JSON에는 해당 시트의 결과만 포함됩니다. 검토 결과는 JSON으로 다운로드하세요.
- 표는 전체 행을 스크롤로 조회할 수 있으며, 화면에 보이는 구간만 렌더링합니다. Excel/CSV 해석은 Web Worker에서 처리하고, 시트 데이터와 컬럼 가공 결과를 재사용합니다. 비어 있는 행은 제거되므로 헤더 선택의 행 번호는 비어 있지 않은 행 기준입니다.
- 이름이 같은 컬럼도 위치 ID로 구분합니다. 파일·시트·헤더 변경 시 기존 분석을 무효화합니다.
- API 응답 스키마, 컬럼 ID, 필드 중복·누락을 검증합니다. 실패 시 원본 API 오류나 키를 노출하지 않고 수동 연결로 진행할 수 있습니다.
- 로컬 단일 사용자 프로토타입이며 루프백 주소에만 바인딩합니다. 조직 배포 시 인증·권한 및 파일 처리 리소스 제한을 추가해야 합니다.

OpenAI 구현 참고: https://developers.openai.com/api/docs/guides/structured-outputs

AI 분석은 현재 **헤더와 대표 행 기반 컬럼 매핑**을 수행하며 전체 거래의 정합성을 검토하지 않습니다. 배출계수 매핑·배출량 산정·거래별 오류 보고서는 아직 포함하지 않습니다. 분석 전에 선택한 시트의 헤더를 확인해주세요. 다른 시트를 분석하려면 업로드 단계에서 시트를 변경한 후 다시 분석합니다. 시트 변경 시 이전 연결과 검토 확정 상태가 초기화됩니다. 진행률은 AI 응답과 매핑 검증이 완료된 예시 행 수를 집계합니다. 결과 JSON에는 원본 행 수와 sampledRowCount, analysisMode를 구분해 기록합니다.

인증 오류는 OpenAI의 실제 401 응답이며 UI에서 숨기지 않습니다. 키 존재 여부 확인과 키 유효성은 별개입니다. 키가 폐기되었다면 유효한 키로 교체해야 합니다.

분석 구간은 기본 최대 3개 동시 처리하며 `reasoning.effort: low`를 사용합니다. `.env`의 `ANALYSIS_CONCURRENCY`(1–3), `ANALYSIS_CHUNK_CHARS`(24,000–96,000)로 조정할 수 있습니다. 일시적인 429는 최대 2회 재시도하고 크레딧 부족은 재시도하지 않습니다. 하나의 구간이 실패하면 나머지를 취소하고 부분 완료 결과를 확정하지 않습니다.

컬럼 연결 화면에서는 구매·입고일자, 품목·서비스명, 품목코드, 공급업체, 구매금액, 통화, 구매·입고수량, 수량 단위, 분류·계정과목, 거래 식별자로 정리한 전체 내역을 확인할 수 있습니다. 미리보기는 LLM의 컬럼 연결을 원본 값에 적용하며, 연결 수정 시 즉시 갱신됩니다. 미연결·빈 값은 채우지 않고 표시하고, 확인 필요 상태를 표시합니다. 표의 ‘컬럼 추가’로 사용자 정의 항목을 만들고 원본 컬럼에 연결할 수 있으며, 추가 항목은 결과 JSON에도 이름과 연결 정보가 포함됩니다. 사용자 정의 컬럼은 삭제할 수 있습니다. 연결 근거는 화면에 표시하지 않습니다.

분석 중에는 업로드한 표를 유지하고 분석 버튼에 진행 상태와 취소 기능을 표시합니다. 완료되면 컬럼 연결 화면으로 이동합니다. 분석 도중 파일·시트·헤더를 변경하거나 다른 단계로 이동하면 진행 중인 요청을 취소합니다.

## 카테고리 스크리닝

첫 화면의 단계형 스크리닝은 사용자가 제공한 Scope 3 순서도의 질문 ID 1.1–5.3을 따르는 결정형 안내입니다. 다른 작업 단계와 동일하게 왼쪽에는 15개 카테고리, 오른쪽에는 질문 1개와 예·아니요 선택, 하단에는 이전·다음 버튼을 배치합니다. 검색, 자유 입력, 외부 API 또는 LLM 호출 없이 진행합니다. 구매·물류, 판매 제품, 임대, 임차, 판매 후 물류를 순서대로 확인하고 Cat 1·4·8·9·10·11·13 및 Scope 1·2 검토 후보와 판단 근거를 표시합니다. 이 순서도 밖의 카테고리를 판정하지 않습니다.

이전 답변 수정 시 그 이후 답변과 결과를 제거하고 새 분기를 계산합니다. 화면을 오갈 때 답변은 유지되지만 새로고침 시 초기화됩니다. Cat 1 결과에서는 자료 검토로 이동할 수 있으며 나머지 카테고리의 실제 산정 기능은 준비 중입니다.

## 산정 조건 확인

컬럼 확인 후 기존 산정·회계 기준, 자료 포함 범위, 자산 구매와 다른 활동의 혼재, 수량·금액의 의미, 운송비, 취소·반품, 품목 상세를 한 질문씩 확인합니다. 이 단계는 정해진 질문과 선택지에 사용자 메모를 받는 방식이며 별도의 LLM 호출은 하지 않습니다. 연결된 컬럼의 첫 3개 원본 값만 근거 예시로 보여주고, 회사 차원의 기준을 파일에서 추정하지 않습니다.

답변 출처는 `user`이며 ‘답변 기록’은 검증 완료를 뜻하지 않습니다. 불확실하거나 추가 자료가 필요한 답변은 확인 요청으로 남깁니다. 원본·시트·헤더·매핑 변경 및 재분석 시 자료별 답변은 초기화하고 회사 답변은 유지합니다. 회사 기준을 변경하면 자료별 답변을 다시 확인합니다. 응답과 미해결 목록은 결과 JSON에 포함됩니다. 원본 행 제외, 기간 필터, 금액 보정, 실제 배출량 산정은 자동 적용하지 않습니다.

범위 참고: [GHG Protocol Cat 1](https://ghgprotocol.org/sites/default/files/ghgp/standards_supporting/Chapter1.pdf), [Cat 2와 회사 회계 기준](https://ghgprotocol.org/sites/default/files/ghgp/standards_supporting/Chapter2.pdf). 이 대화가 기업의 모든 보고 요구사항을 판정하는 것은 아닙니다.

회사·사업장 등록과 산정 기간 질문은 산정 조건 흐름에서 제외했습니다. 남은 질문은 모두 아이콘이 있는 선택 카드로 표시하고 추가 설명은 접이식으로 제공합니다. 추가 확인이 필요한 항목에는 담당 부서·이름 기록과 요청 문구 복사를 사용할 수 있습니다.

## 거래 묶음과 산정 방법 선택

산정 조건을 정리한 후 ‘거래 묶음 확인’으로 이동합니다. 기본 묶음은 품목코드·품목명·공급업체·분류·단위·통화가 일치하는 행으로 구성합니다. 공백·유니코드 표기를 정리하되 품목과 단위의 대소문자는 보존합니다. 품목 식별 정보가 없는 거래는 개별로 유지합니다. LLM의 의미 유사도 군집화가 아닌 명시적인 컬럼 값 기반 묶음입니다.

사용자는 원본 컬럼 값의 ‘같음/포함’ 조건으로 그룹 규칙을 추가·삭제하거나 우선순위를 올릴 수 있습니다. 규칙 조건은 대소문자를 구분하지 않으며 첫 번째로 일치하는 규칙이 적용됩니다. 특정 거래를 따로 묶으려면 데이터 행 번호 조건을 사용합니다. 규칙이 일치해도 단위·통화가 다르면 분리합니다. 규칙·자료·컬럼 연결을 변경하면 기존 그룹 방법 선택은 초기화됩니다.

그룹의 원본 거래를 확인한 뒤 공급업체 자료 / 구매량 자료 / 구매금액 자료 / 보류 중 한 가지 방법을 선택합니다. 수량·단위 또는 금액·통화의 기본 형식을 검사하지만 적합한 배출계수·산정 범위까지 검증한 것은 아닙니다. 공급업체 제품별 탄소자료는 다음 계수 연결 단계에서 확인할 대상입니다. 보류에는 사유가 필요합니다.

JSON에는 모든 데이터 행의 단일 그룹 소속과 방법, 미확인·보류·계수 대기 상태를 포함합니다. 배출량 합계는 아직 계산하지 않으며 거래를 자동 제외하지 않습니다.

### ERP 원본 의미별 컬럼 연결

컬럼 연결은 회사·기간, 거래 추적, 구매 대상, 공급처, 수량·반품, 금액의 여섯 영역으로 구성됩니다. 주문·입고·청구 날짜 및 수량·단위를 각각 보존하고, 규격·제조사·반품·취소·할인·환불·세금·부대비용을 별도 연결합니다. 모든 항목이 필수인 것은 아니며 원본에 없는 항목은 null입니다. 영역별 탭, 원본 전체 보기와 사용자 추가 컬럼을 지원합니다.

이 단계는 산정 기준을 선택하지 않습니다. 입고수량 등을 기존의 일반 구매수량 필드로 자동 대체하지 않습니다. 공통 수량 기준을 사용자가 승인하면 해당 수량·단위 컬럼이 후속 거래 묶음에 적용됩니다. 미확인 또는 거래마다 기준이 다른 경우 수량을 임의로 대체하지 않습니다.

### 산정 조건 확인의 세 단계

자료의 범위·누락 → 제품·서비스 식별 → 수량·금액·단위 순서의 객관식 질문입니다. 사용자의 답변에 따라 빠진 기간/사업장, 반복 행의 의미, 품목 참고자료, 주문·입고·청구 차이, 포장 단위 자료 질문을 표시합니다. 부모 답변을 수정하면 더 이상 해당하지 않는 후속 답변은 제거하며 요약·다운로드의 확인 목록에서도 제외합니다. ‘잘 모르겠어요’는 추가 입력 없이 미해결로 기록합니다. 원본 예시는 연결된 컬럼에서만 가져오며 파일만으로 누락·중복을 확정하지 않습니다. 별도 자료가 있다는 답변은 자료 확보 완료나 업로드로 취급하지 않습니다. 밀도 환산은 배출계수 연결 후 필요성을 확인하도록 안내하며 현재 단계에서 자동 환산하지 않습니다.

추가 자료 입력: 별도 파일·품목대장·사양표가 있다는 답변 다음에는 자료 첨부 화면이, 원본의 다른 컬럼이라는 답변 다음에는 복수 컬럼 선택 화면이 표시됩니다. 상세 기준이 필요한 답변에는 텍스트 입력 화면이 표시됩니다. 각 화면에서 나중에 추가할 수 있습니다. 첨부는 파일당 10MB, 질문당 5개·총 20MB까지 현재 세션의 답변에 실제 파일 내용(data URL)으로 보관하며 준비 내용 JSON 다운로드에 포함됩니다. 첨부 파일의 자동 분석·거래 연결은 수행하지 않고 추가 확인 상태를 유지합니다.

### 공통 기준과 데이터 기반 예외 검토

고정 설문을 순서대로 진행하는 대신, 원본 전체를 로컬에서 검사해 공통 기준(포함 범위, 연결된 수량·금액)과 문제별 확인 항목을 만듭니다. 반복 구매번호, 코드 형태의 품목명, 동일 코드의 서로 다른 품목명, 같은 단위에서의 수량 차이, 음수·빈 값·숫자 형식, 포장 또는 불명확한 단위를 묶어서 보여줍니다. 탐지는 결정적 규칙이며 LLM의 제품 판정이나 배출계수 적합성 판단이 아닙니다. 영향 행 수는 표시하지만 이를 배출 영향 순위로 해석하지 않습니다. 사용자가 원본 전체/해당 행을 확인하고 공통 기준을 승인하거나 나중에 확인할 수 있으며, 미확인 사항은 요약과 다운로드에 유지됩니다. 질문 조건에 따른 자료 첨부 흐름도 유지됩니다.

승인한 구매수량 기준은 원본 컬럼 연결을 변경하지 않고 후속 거래 묶음의 수량·단위 입력으로 적용합니다. 예를 들어 입고수량 승인 시 입고수량과 입고단위를 사용하며 주문단위를 대신 사용하지 않습니다. 제품 분류·배출계수 연결 및 실제 배출량 계산은 아직 수행하지 않습니다.

### 서비스 제공 업계 평균 계수와 계산

`GET /api/factors`가 EPA 공식 Supply Chain GHG Emission Factors v1.3.0 CO2e CSV(2022 USD)를 서버에서 조회합니다. 캐시된 단일 요청을 공유하며 1,016개 항목·스키마·단위·유일 코드·유한 비음수 계수를 검증합니다. 원본 조회 실패 시 503을 반환하고 가짜 대체값은 사용하지 않습니다. 공급 데이터는 미국 산업별 구매금액 평균입니다. 구매량 계수와 공급업체 제품별 계수는 아직 지원하지 않습니다. Cat 1 대상 여부와 미국 평균 적용 가능성은 사용자가 검토합니다. SEF(생산 단계까지, 유통 마진 제외)를 사용하며 MEF를 자동으로 더하지 않습니다.

품목명·분류의 키워드와 제한된 한영 동의어로 후보를 검색하며, 이는 LLM 의미 분류가 아닙니다. 불명확한 코드에 자동 계수를 할당하지 않습니다. 사용자가 품목 분류·지역·범위를 확인해 계수를 연결합니다. 동일 코드·품목명·분류의 미확인 묶음은 명시적으로 선택해 한 번에 금액 방식과 같은 계수를 적용할 수 있으며, 기존 승인과 보류는 덮어쓰지 않습니다.

각 원본 통화마다 구매연도, USD/원본통화 환산율, 2022년 가격으로 보정하는 배수, 근거를 입력·승인해야 합니다. 단순 환율 변환을 기준연도 보정으로 간주하지 않습니다. 승인된 금액 × 환산율 × 가격 보정 × 계수로 행별 계산합니다. 관련 조건 미확인·음수·누락·환산 근거 없음·계수 미연결은 합계에서 제외하고 사유를 유지합니다. 다운로드에는 원본 행, 계수 스냅샷, 원본 조회시각·SHA256, 환산 기준, 행별 계산값과 미산정 사유가 포함됩니다. 현재 개발 환경의 외부 DNS 제약으로 실제 EPA CSV 다운로드는 검증하지 못했으며, 원본 형식에 맞춘 합성 fixture로 파서·조회 오류·계산을 검증했습니다. 실제 원본의 첫 연결 검증은 필요합니다.

### 자동 산정 검토 화면

세 가지 방법을 처음부터 선택하는 화면 대신 자료·지원 계수 기반 방법 제안과 미해결 이유를 먼저 표시합니다. 현재는 금액·통화와 금액 계수 후보가 있을 때 구매금액 방식을 제안합니다. 계수 후보 복수/없음, 환산 기준 누락, 산정 조건 미확인 등을 따로 표시하고 실제 계산 완료된 묶음은 기본 확인 목록에서 제외합니다. 계수를 승인하면 제안된 금액 방식도 함께 적용합니다. 원본 확인과 수동 방법 변경은 접힌 영역에서 가능합니다. 공급업체·수량 계수가 아직 없어 세 가지 방법의 완전한 자동 비교는 지원하지 않습니다. 키워드 후보가 하나여도 제품·지역·산정 범위 적합성 승인으로 간주하지 않습니다.

### LLM 제품 의미 분류와 내부 코드 확인

`POST /api/classify-products`는 제품명·설명·규격·제조사와 사용자 설명을 바탕으로 제품 의미·소재·용도를 분류하고 서버가 제공한 계수 ID만 최대 3개 제안합니다. 원본 거래 전부를 모델에 보내지 않고 코드·품명·공급업체·분류별로 중복을 제거한 대표 정보(서로 다른 규격 포함)를 20개씩 순차 처리합니다. 숫자 계수는 모델에 요청하지 않으며 결과 ID를 서버 목록과 대조합니다. 입력과 결과 크기, 누락·중복 ID, 불일치 상태를 검증합니다. 원본 문자열을 지시문으로 취급하지 않도록 명시합니다. 오류·취소·미완료 응답은 성공으로 저장하지 않습니다.

코드만 있는 제품은 추정하지 않고 사용자에게 이름·소재·용도를 묻습니다. 설명은 현재 파일/시트의 동일 코드·품명·공급처 범위에 재사용하고 원본 값을 바꾸지 않습니다. 설명 변경 시 해당 품목의 방법·계수 승인을 해제해 다시 검토합니다. 설명 삭제와 재분류도 가능합니다. 동일 코드에 여러 사양이 있을 경우 LLM에 차이를 전달하여 질문하도록 요구합니다. 분류 제안과 사용자 설명은 결과 JSON에 보존됩니다. 외부 네트워크 제약으로 실제 API의 의미 분류 품질은 아직 검증하지 못했고, API 요청/결과 검증과 경계 조건은 모의 응답으로 검증했습니다.

한국 데이터: KEITI 국가 LCI DB 및 환경성적표지 평가계수가 존재합니다. LCI 투입·산출물은 바로 CO2e 단일 계수가 아니므로 원본 버전·기능단위·시스템 경계와 탄소발자국 산출 기준을 확인해야 합니다. 한국 데이터의 실제 서비스 인입은 아직 수행하지 않았습니다. 공식 안내: https://www.keiti.re.kr/site/keiti/02/10202100000002023101610.jsp / 공공데이터 안내: https://www.data.go.kr/data/15120968/fileData.do

### 간소화된 시연 화면 (현재 기본 흐름)

현재 기본 UI는 SimpleMethodReview이며 품목 선택 → 제품 설명(필요할 때) → 분류 제안 적용 → 시연 결과만 보여줍니다. 원본과 직접 예시 분류는 접힌 영역입니다. EPA 조회와 통화·연도 보정 설정은 기본 흐름에서 제거했습니다. 로컬 DEMO_FACTORS의 가상 KRW 금액 계수를 사용하며 이 값은 한국 공식 배출계수가 아닙니다. LLM도 demo-example 요청에서는 이 예시 목록만 전달받고 EPA를 조회하지 않습니다.

예시 계산은 calculateDemo로 분리되며 실제 calculateEmissions는 예시 계수를 거부합니다. 시연에서도 구매금액 산정에 관련된 미확인 조건의 영향 행은 계산에서 보류하며 실제 산정 완료로 취급하지 않습니다. 결과 JSON에 demo/notForReporting/notice를 기록하고 emissionsCalculated=false로 유지합니다. 다운로드명도 DEMO-not-for-reporting으로 표시합니다. LLM 연결 실패 시에는 오류를 표시하며, 사용자가 ‘예시 분류로 직접 시연하기’를 명시적으로 선택하면 예시 계산 흐름을 확인할 수 있습니다. 이를 AI 분류 성공으로 기록하지 않습니다.


### 여러 품목 설명 일괄 입력

‘여러 품목 한 번에 설명’에서 품목·서비스명 또는 품목코드를 선택하고 숫자 코드 범위(양 끝 포함)나 쉼표/줄바꿈 목록으로 현재 자료의 품목을 찾습니다. 적용 전 품목·공급처·거래 수를 확인하고 예외를 해제할 수 있습니다. 기존 설명은 기본적으로 유지하며 명시적으로 교체할 수 있습니다. 공통 설명은 선택된 품목에 저장되고 해당 품목의 기존 방법·계수 승인만 해제됩니다. 제품을 병합하거나 같은 계수를 강제하지 않습니다. 범위 규칙을 향후 업로드에 자동 적용하지 않습니다. 편집 영역에 산정법·공식·적용 상태를 표시하며 현재 시연 경로는 구매금액 기반입니다.

산정 조건 화면은 표시된 공통·예외·후속 질문에 모두 응답해야 다음 단계로 이동합니다. 모름/추가 확인은 완료로 승격하지 않습니다. 제품 식별과 코드 일관성은 사용자 확인을 받으며, 수량 기준·수량 차이·포장 환산은 현재 금액 방식의 계산 차단 사유에서 제외합니다. L→kg 등 계수 단위에 따른 확인은 수량 계수 연결 기능과 함께 구현해야 합니다.


### Cat 1 템플릿 기준의 두 산정 방법 (현재 UI)

SimpleMethodReview는 중량 기반(성분·성분별 비중, 입고중량, 중량단위)과 비용 기반(US EEIO 중분류, 구매금액, 통화, 원화금액, VAT 포함 여부)을 점검합니다. 두 방식의 자료와 후보 계수가 있으면 중량을 우선합니다. 계수가 없거나 필수 정보가 부족한 경우 해당 방식은 적용하지 않습니다. 공통 필수는 입고일자·구매품목명·구매 유형·대분류이며 자본재는 Cat 2 검토로 보류합니다. 원화금액은 초안 B46에 기재된 추가 조건을 반영해 매핑 항목에 추가했습니다.

현재 계산은 여전히 시연용입니다. 가상의 kg CO2e/kg 및 kg CO2e/KRW 계수만 사용하며 실제 한국 계수나 US EEIO 계수와 혼동하지 않습니다. 질량은 명시된 g/kg/t만 환산하며 EA/L을 kg으로 자동 환산하지 않습니다. 원화 거래는 원본 금액을 원화금액으로 사용할 수 있으며, 외화는 명시된 원화금액이 필요합니다. 시연 계수는 VAT 제외 금액 기준이며 포함된 경우 명시된 원화 세금만 차감합니다. 외화 세금을 임의 환산하거나 VAT 세율을 추정하지 않습니다. 실제 계수 연결 시에는 해당 계수의 가격 기준·통화·연도·세금 범위에 맞는 보정이 별도로 필요합니다.

묶음별 사용자 확인값은 원본을 변경하지 않고 별도 저장하며 변경 시 기존 계수·방법 승인을 해제합니다. 서로 다른 성분·중분류가 섞이면 공통 기준 확인 또는 묶음 분리가 필요합니다. 결과는 원본 행별 단일 방법·활동량·계수·미산정 사유를 보존합니다. 실제 보고용 계산은 아직 아니며 emissionsCalculated=false를 유지합니다.
